# ADR 0002 · Team identity options

M0 reviewed upstream identity options. Runtime authorization and team deployment are M3 gates.

| Option | Assessment |
| --- | --- |
| MLflow 3.18.0 native basic auth and workspaces | Candidate fallback for per-user and machine credentials. Use a separate PostgreSQL auth database, a generated admin credential, disabled automatic default-workspace access, and explicit grants with a denying default. Test viewer mutations, known IDs, logged models, model versions, aliases and artifact APIs before release. Provision identities separately from Keycloak if this fallback is selected. [MLflow basic auth](https://mlflow.org/docs/latest/self-hosting/security/basic-http-auth/) · [Workspace permissions](https://mlflow.org/docs/latest/self-hosting/workspaces/permissions/) · [RBAC](https://mlflow.org/docs/latest/self-hosting/security/role-based-access-control/) |
| Keycloak with community MLflow plugin | `mlflow-oidc-auth` 11.5.0 declares `mlflow>=3.16.0,<4`, which includes 3.18.0. Upstream advertises browser OIDC, JWT workload identities and workspace restrictions. Dependency metadata establishes eligibility for evaluation. Validate token issuer, audience, expiry, callback and group mapping, permission bypass paths, and revocation with the selected stack before approving it. [MLflow SSO](https://mlflow.org/docs/latest/self-hosting/security/sso/) · [Plugin release and metadata](https://pypi.org/project/mlflow-oidc-auth/11.5.0/) |
| RustFS with Keycloak | Upstream documents Console OIDC and local claim-to-policy mapping. Use scoped S3 service credentials for automation until STS exchange, expiry and revocation are tested on the selected release. [RustFS OIDC](https://docs.rustfs.com/en/security-compliance/oidc) · [RustFS credentials](https://docs.rustfs.com/en/operations/credentials) |
| Gitea with Keycloak and trusted ingress | Configure a dedicated provider/client and test repository permissions and group/revocation behavior, including actual Git HTTP access. Ingress authenticates and terminates TLS, with service authorization enforced per resource. [Gitea command line](https://docs.gitea.com/administration/command-line) · [Keycloak reverse-proxy guidance](https://www.keycloak.org/server/reverseproxy) |

Ship shared access only after the integration suite can demonstrate cross-project and viewer denials at direct API and artifact endpoints. If the chosen MLflow mode cannot enforce those boundaries or limit alias writes, use a separate instance per trust boundary or keep the single-user deployment. Native workspace membership or reverse-proxy login alone is insufficient evidence. M0 did not deploy an identity provider or run these authorization checks.
